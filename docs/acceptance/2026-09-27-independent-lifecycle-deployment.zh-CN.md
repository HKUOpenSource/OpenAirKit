# OCUDU 0.6.0 实机部署与生命周期验证

日期：2026-09-27。源码基线：`39dde4d0216dee973ed6cbf40ecb500e83c1ac74`
及已审阅、尚未提交的生命周期改动。两台已完成站点初始化的 ARM64 Jetson 均从
0.5.1 升级至 0.6.0。Spark 更新独立启停脚本，监测应用仍为 0.2.0。

## 部署标识与边界

- Jetson 发布号：`8ade791a3317ad5e`；两台设备安装后的 51 个清单文件全部匹配。
- 清单 SHA-256：`e297880d5a4ac2ec4f04395efbf76e113d7e61c62a977c62a8f0edee1340ae40`。
- 维护授权：`0b30462ac4a898a8c5f398114f682bdc0fc0c4a8acab826ef51597734329d127`。
- Spark 生命周期控制脚本 SHA-256：`b2867227b14f3678824cdb214bcea6c858c0430beaf7c4d028c4775db785549a`。

操作员在两台 Jetson 激活了匹配的受限授权。安装使用精确批准的发布包，沿用已有
站点初始化和认证。安装器保留了回滚检查点，旧快捷脚本另有备份。安装只启动 Web，
设备执行器保持停止，两项 Jetson 服务仍关闭开机自启；快捷脚本来自校验后的新版包。
本轮不需要且未执行应用版本回滚。

验证问题是：完成首次站点配置后，OCUDU 能否独立准备、运行和清理自己的资源。
调用路径见[开发验证记录](2026-09-27-independent-lifecycle.zh-CN.md)。现场既有
服务通过其自身入口停止以释放共享资源；此后 OCUDU 的启停没有使用外部准备脚本、
手动插入数据路由或手动退出维护模式。未调用恢复任务或重置模组。管理网络配置仍是
明确的站点前置条件。

## 实机结果

| 操作耗时，秒，含 SSH | Spark | Jetson A | Jetson B |
| --- | ---: | ---: | ---: |
| 升级 | 脚本替换 | 12.45 | 11.70 |
| 首次启动 | 36.43 | 2.58 | 2.63 |
| 重复启动 | 0.85 | 1.27 | 1.86 |
| 停止 | 2.92 | 1.47 | 1.37 |
| 重复停止 | 0.63 | 1.35 | 1.22 |
| 完全停止后再次启动 | 36.36 | 3.74 | 3.39 |
| 最终停止 | 3.55 | 1.59 | 1.49 |

服务启动耗时不等于 UE 已接入。首次采样时双设备均有新鲜的已验证证据，距首次
Spark 启动开始 99.8 秒。完整停止/启动后，在距 Spark 启动开始 106.7 秒时再次
确认双设备通过；重新接入观察器本身等待 22.3 秒。这些是采样上界，不是精确注册延迟。

- 两次启动均有 12 个健康 Open5GS 容器、唯一成功的 N2 NG Setup 和健康 Spark
  监测。核心网记录两个已注册、已连接用户，均有活动 PDU，会话地址摘要不同。
- 两台 Jetson 均有新鲜注册、活动 PDU、已验证数据路径、管理保护；观测开启，自动恢复暂停。
- 完整循环前后，两台的网关、UPF、ext-DN、公网 ICMP 及 ext-DN HTTP 全部通过，
  探测绑定各自模组接口，没有用 Wi-Fi 代替蜂窝数据验收。
- 两段完成的稳定观察分别持续 61.1 和 60.8 秒，每段 7 个样本，双设备全部通过；
  每次检查要求证据年龄不超过 20 秒。
- 重复启动保持所有服务 PID 和单调启动时间不变，重启计数为零；重复停止成功。
- 每台 Jetson 自建一条主机路由，复用已有正确路由；停止时清理，启动时重建。
  两次清理检查均无协议号 186 的残留路由，其他主路由表记录逐项保持不变。
- 停止释放两台 Jetson 的监听端口和设备 socket；Spark 没有残留的 OCUDU 容器
  或服务进程。安装前及两次 OCUDU 运行期间，均确认两台设备的 SSH 流量经 Wi-Fi。

## 保留的问题与验收范围

最初的私有核心网采样脚本假设每条 AMF 上下文都有身份，遇到一条无 SUPI、已注销且
空闲的上下文时报错。已将只读采样器改为单独列出此类记录，没有修改应用或核心网
数据。两个有身份的活动会话通过；下一次完整启动没有这条无身份记录。本记录不保存
生产身份或地址。

最初一段稳定观察到第 54 秒时，状态读取与重复启动争用了维护助手的互斥锁，导致
采样器中断，运行服务未中断。该段没有计入通过；两段完成的观察均在启停写操作结束
后进行。这符合不并发执行维护操作的既有约束，没有绕过锁或权限。

本轮验证的是两台已有初始化的安装升级及两次有界 OCUDU 运行。未执行 0.6.0 全新
密码设置/commissioning、实机应用回滚、拔除故障注入、五次耐久循环或吞吐压测。
此前单元与隔离 Linux 测试仍是独立证据。私有操作记录与采样保存在忽略目录
`local/independent-lifecycle-20260927/`。没有重新导入订阅或回滚鉴权状态。

## 最终状态

两台 Jetson 保留 0.6.0 安装及匹配的维护授权，Spark 保留新版启停脚本。OCUDU
所有服务停止，Jetson 开机自启仍关闭，自有路由无残留。验收后恢复原 OAI 运行状态：
Spark 服务就绪耗时 23.65 秒，两台 Console 启动耗时分别为 13.00 和 14.78 秒。
在 Spark 恢复启动后 233.5 秒观察到两个预期活动会话，未超过 300 秒上限。最终
两台控制台健康、核心网会话地址不同，绑定模组的网关、UPF 与公网探测全部通过。
没有通过重置来加速第二台设备重新接入。

文档审计、发布边界审计与 `git diff --check` 通过。部署过程中未修改被验收的
应用包，仅修正私有证据读取脚本。本结果不代替路线图中的完整故障矩阵、全新安装、
回滚或耐久验收。
