# Astryx 控制台迁移 — 2026-09-23

[English](2026-09-23-astryx-ui.md)

Jetson Console 与 Spark Platform 已改用 Astryx 官方组件及未经修改的 Neutral
主题。Spark 0.2.0 和 Jetson 0.5.1 已部署到真机，验证结果及运行限制见
[初次部署记录](2026-09-23-astryx-deployment.zh-CN.md)和
[Jetson 实时更新修复](2026-09-23-jetson-live-stream.zh-CN.md)。

## 范围与组件映射

| UI 区域 | 官方组件 |
| --- | --- |
| 应用导航、移动导航 | AppShell、TopNav、SideNav、SideNavItem、DropdownMenu |
| 页面布局、拓扑证据 | Stack、Grid、Card、Heading、Text、Link |
| 表单与筛选 | TextInput、Selector、SegmentedControl、Switch、Button |
| 状态、错误与空内容 | Badge、Banner、Spinner、EmptyState |
| 证据与任务详情 | Table、MetadataList、Collapsible、ProgressBar |
| 操作确认 | AlertDialog |
| 信号与指标历史 | Charts 的 Chart、ChartAxis、line |

已移除原有自定义样式和手绘 SVG 图表。拓扑改为包含链接与状态标签的证据卡片。
共享 CSS 仅使用官方主题令牌设置页面尺寸、换行与间距。少量本地包装函数负责
将领域状态映射到官方 Badge，或向官方组件传入数据，不另行实现控件。
Lucide 图标与 Neutral 主题使用同一依赖版本。

## 依赖约束

两端 Core、Neutral 和 Charts 均固定为 `0.6.2-canary.d72e4d6`。
Charts 要求对应的 Core 预发布版本；将稳定版 Core 0.6.2 与该 Charts 混用
不满足其 peer dependency。StyleX 固定为 0.19.0，Lucide React 为 1.18.0。
所有依赖锁文件均为版本管理中的构建输入。

为实现全套 Astryx，当前采用 Charts 预发布版本。后续应同时升级三个 Astryx 包，
并重新运行浏览器验证。运行时不需要访问 npm/CDN，代码和官方 CSS 均由 Vite
打包。构建同时输出 `THIRD_PARTY_NOTICES.txt`，并补入两个 npm 包遗漏的固定
版本上游许可证。合并后的 JS 包目前会触发 Vite 的 500 kB 分块建议；若设备实测
表明有必要，可进一步评估按路由加载。

## 问题、调用路径与影响

问题：能否在保留硬件操作与证据语义的前提下，将两个现有 React 控制台完整接入
Astryx 官方组件？仓库没有 `.codegraph/` 索引，本次检查了源码、包类型及已发布
组件实现。

- `main.tsx → UIProvider → Theme / LinkProvider → AppShell → 路由页面`：
  管理主题、客户端路由、无障碍导航与移动抽屉状态。
- Jetson `api / SSE → App → 页面上下文 → Fields / JobPanel / MiniChart`：
  保留调试完成检查、CSRF、手动执行、恢复、维护、过期证据及诊断导出。
- Spark `api / SSE → freshView → 页面组件 → Trend`：保留指标归属、注册与
  连通性区分、当前值过期语义、历史值、单位及所选时间窗口。
- 图表适配器转换时间戳与有效数值，保留空值断线，Spark 长时间采样缺口也会断线。
  单个 Spark 采样点仍位于所选时间窗口中的正确位置。SSE 独立更新当前值，
  不等待历史查询刷新。
- `vite.config.ts → frontendLicenses → dist/THIRD_PARTY_NOTICES.txt`：
  将浏览器依赖声明纳入现有发布产物。

UI 迁移保留后端 API 路径、设备配置、无线/核心网控制协议及部署目录。
用户随后要求的 Identity 调整改变了订阅设备的显示数据，具体见下文。
此前用户单独要求的 P2 被动速率修复仍保留在工作区。

## 验证

- 两端 TypeScript/Vite 生产构建。
- `make check VENV=local/bootstrap-check`：后端/协议栈测试、类型检查及审计。
- `make e2e-jetson VENV=local/bootstrap-check`：模拟器登录、四个页面、手动任务
  恢复/取消、恢复操作、CSRF 拒绝、断流、认证过期、抽屉关闭，以及 1440/390 px
  无横向溢出。
- `make e2e-spark VENV=local/bootstrap-check`：三套原有浏览器用例适配官方组件
  语义，覆盖导航、详情、安全的设备状态、筛选、确认、退出、断流、过期历史、
  单位、单点位置、SSE 当前值与图表断线，并验证 1440/390 px。
- 视觉检查仅使用本地合成数据，未对真实设备执行操作。

## Device Identity 后续调整

按用户要求，`open5gs.parse_info → collector → 已鉴权 snapshot / devices API
→ DeviceTable` 现在以字符串传递完整订阅设备数字编号，保留开头的零。AMF 关联
记录与仅由 SMF 提供的记录均遵循此规则；资源的哈希 ID 与关联校验不变。历史
记录若只保存了脱敏值，需要再次采集才能获得完整编号，不能从末四位还原。

订阅设备列表保留 Identity、State、PDU addresses、DNNs、Last seen。移除冗余的
来源副标题和行尾详情链接，点击 Identity 即可进入详情页查看来源与关联信息。
无线指标列仍保留在无线上下文视图。宽表格使用 Astryx 内置、支持键盘访问的
横向滚动容器，并设置可读列宽。

诊断导出继续对身份脱敏，采集事件消息保留脱敏订阅标签。测试使用合成编号，
覆盖前导零、已鉴权显示与搜索、诊断脱敏、列表列集合及手机表格滚动。
真实设备编号与截图不写入仓库。
