## Scope and implementation

Each Jetson console owns its local device state. Spark displays evidence available
at its own base station. No fleet inventory, mandatory device identity banner or
global device state was added. Both consoles retain Astryx Core, Charts, Neutral
and their existing UIProvider; the only added CSS selects the responsive Setup
composition. Runtime text remains English.

The repository has no CodeGraph index. The review question was: which UI data
paths misrepresent local state, hide errors or prevent access to retained evidence?

| Call path | Correction and impact |
| --- | --- |
| Spark `freshView` / `freshDevice` → `activeDataSession` → Overview / Devices | Active requires fresh, registered, explicitly active data PDU evidence. Registration, session and freshness filters are separate. Subscriber filtering no longer offers an unattainable Connected state; empty filtered results explain how to recover. |
| Jetson confirmation → `confirmOperation` → jobs / run | Remember a created task before requesting execution. Retry first reads that task and runs only a ready/paused recovery; it never creates a second task after a known creation. Failure text remains inside the Astryx confirmation dialog. Setup still requires separate execution confirmation. |
| Jetson JobPanel / maintenance; Spark Operations → API | Show pending states and disable competing actions. Spark history polling owns a separate error from submission/cancellation, so successful reads cannot erase an operation error. |
| Jetson History / recent activity → history / metrics | Refresh independently of task count, abort superseded reads, consume the event cursor and retain older loaded pages until explicit refresh. Show the 30-day event versus 7-day metric retention limit. Charts identify the last valid sample and use the selected time domain, including dates for multi-day windows. |
| Spark History → authenticated history/catalog → Store | Page through retained entities, including offline ones, and metric names from retained samples. This does not depend on the current snapshot containing the entity or metric. |
| Spark Events → authenticated events/kinds → Store | Derive type choices from retained event categories independently of filtered pages. Abort superseded reads and protect loading state from obsolete completions. |
| gNB → Astryx summary / Collapsible / Trend → HistoryProvider | Prioritize N2, radio contexts and traffic. Group signal, host and runtime detail under closed disclosures. Share each entity/window/refresh request across charts; bound the cache and discard it when the authenticated tree unmounts. |
| Jetson Setup → Astryx Table / Card / MetadataList | Explain Matched, Different, Observation only and Unknown. Compare addresses against pool validity, expose prerequisites and planned actions, and keep current/target/assessment together below 768px. No modem lock is inferred from observed radio policy. |
| Spark shell / StatusSummary → Astryx SideNav / Banner | Move history, operations and diagnostics to primary navigation. Label collection as Live data / Evidence stale, translate diagnostic reasons and format timestamps consistently. Distinguish initial sign-out from expiry and provide retry after failed initial status loading. |

## Validation

- Frontend behavior tests: seven passed, covering active/inactive/unknown/expired
  evidence, recovery retry identity, setup separation, concurrent chart request
  sharing, failed-history retry and initial authentication probing.
- Spark backend suite: 59 tests run, 58 passed and one existing macOS skip.
  New API tests cover authentication, independent event categories, paginated
  offline entities and metric names absent from the latest sample.
- Both frontend production builds and TypeScript checks passed. The existing
  large-bundle warnings remain; this change does not claim reduced bundle size.
- Documentation, release-boundary, license/ownership and whitespace audits passed.
- Existing browser fixture scripts were updated for the new navigation, filters,
  metadata endpoints and disclosures; their JavaScript syntax was checked.
  The standalone browser suites were not run in this session.
- In-app Browser inspection used synthetic loopback services. Setup, Jetson
  History, gNB, Devices and Events had no page overflow at 390/768/1024/1280px.
  Mobile Setup cards and gNB priority order were visually inspected.
- Confirmed 100 → 125 event pagination, stable event type choices after filtering,
  explanatory device filter empty states, first-login wording, failed-load retry,
  and confirmation focus returning to its trigger. These are focused checks,
  not a complete keyboard, screen-reader or 200% zoom certification.

## Authorized simulator workflow acceptance

After explicit user authorization, Browser exercised the real local web APIs with
Jetson simulation enabled and an inert Spark executor on a temporary Unix socket.
No production device, radio command, deployment or external service was involved.

- Jetson: a delayed failed Setup submission kept the error in the confirmation
  dialog. Retry created one manual plan; execution paused after one step and
  cancellation completed. Run and cancel were disabled while cancellation was
  pending.
- Jetson recovery: creation succeeded but the injected run request failed. Retry
  first read the original task, then ran that same ID to completion. Request
  records confirmed that retry did not create another task.
- Spark: delayed submission showed a loading/disabled confirmation button. Its
  failure remained inside the dialog after three successful background polls.
  Retry created a simulated running task. A cancellation error remained visible
  after eleven successful polls; retry cancelled the task and re-enabled controls.
- At 390px the Jetson error dialog fit without overflow, and Back returned focus
  to Create setup plan. Removed a duplicate “Error:” prefix found during this check
  and rebuilt the Jetson frontend successfully.

The earlier automatic-approval rejection was resolved by the user's explicit
simulator authorization. These focused workflow checks now pass. Full keyboard,
screen-reader, 200% zoom and live hardware acceptance remain outside this run.
Synthetic services and viewport overrides are cleaned up after inspection.
