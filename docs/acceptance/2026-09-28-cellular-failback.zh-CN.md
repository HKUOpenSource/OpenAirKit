# 蜂窝默认路由自动切回 — 2026-09-28

## 问题与原因

蜂窝恢复后，是否会自动替换 Wi-Fi 默认出口？修复前不会。
`Agent.auto_reconcile` 在注册和数据 PDU 有效时直接返回；
`network.helper(promote)` 只安装绑定蜂窝的探测主机路由，并要求 Wi-Fi 保持
首选默认出口。因此公网探测成功不能证明普通 IPv4 流量走蜂窝。USB 重新枚举后，
NetworkManager 可能自行安装蜂窝默认路由，这解释了不同时刻、不同设备的表现差异。

两台 Jetson 的只读检查确认内核未启用策略路由。本次使用主路由表实现切换，
不声称 Tailscale 管理连接具有独立的 Wi-Fi 底层传输。

## 调用路径与影响

`Agent.serve -> sample -> reconcile_routes -> Network.action -> network.helper ->
managed_routes / managed_defaults -> 精确 iproute2 操作`。
当前仓库没有 `.codegraph` 索引，调用路径通过源码检查确认。

- 连续两组完整、新鲜且包含公网的成功探测后优先蜂窝；连续两组失败后回退 Wi-Fi。
  注册、PDU、接口丢失或证据超过 20 秒时，在下一次协调中回退，正常采样间隔为
  10 秒。重复读取或只更新部分探测不算第二组。注册、会话、无线或接口变化会重置确认。
- 路由自动切换独立于自动模组重置开关，不写模组。任务等待或暂停时，证据过期也会回退。
- 自有默认路由使用协议号 186，Wi-Fi 回退 metric 为 5、蜂窝为 10，保留原系统
  默认路由和 NetworkManager 配置。遇到外部高优先级路由或归属不确定则报错停止。
- `egress-state.json` 单独记录默认路由所有权，`network-state.json` 记录探测主机
  路由。添加操作超时会保留不确定记录；清理不会删除已被修改或外部拥有的路由。
- Wi-Fi 回退期间探测仍绑定蜂窝。USB 重新枚举时只替换归属明确的路由；管理器完整
  停止时清理两类日志，模组不在也可清理。
- systemd 在设备执行器启动前和停止后选择回退；进入维护模式先回退再释放串口。
  普通 IPv4 出口使用诊断主机路由之外的目标读取。

Wi-Fi 必须保留地址和唯一网关，到配置的 Spark 地址仍须经 Tailscale；原有默认
路由 metric 必须大于 10。切换可能短暂重连 Tailscale；`management_protected`
只表示回退条件可用，不表示管理传输独立或保证不断线。本次不涉及 IPv6 自动切换。

Web 和设备服务均 active，无自动重启，开机自启仍为 disabled。未修改 Spark 生产服务。

每台启动后均自动选择自有蜂窝默认路由。随后通过已授权的维护动作切到 Wi-Fi

确认后，由后台协调器删除自有 Wi-Fi 默认路由并选择蜂窝（metric 10）。原系统
Wi-Fi 和模组默认路由的 metric 30000、100 始终保留。
