## 审阅发现

1. **P1 — 管理连接保护没有验证隧道的实际传输路径。**
   `network.inspect_management` 只检查 Wi-Fi 有唯一地址，以及到 Spark 的路由
   使用配置的 Tailscale 接口，没有确认隧道实际走 Wi-Fi 还是实验 RNDIS 链路。
   `Network.snapshot -> Agent.auto_reconcile/Agent.write -> modem.write`
   在允许恢复和模组写操作前信任此结果。如果 Tailscale 使用数据链路，即使
   `management_protected=true`，重置模组也可能中断管理连接。模拟复现显示，
   只查询一次虚拟网络目标路由就会返回 true。此前的
   [实机记录](2026-09-23-connectivity-only.zh-CN.md)也记载了 Tailscale 优先使用
   实验链路、恢复测试另走独立 Wi-Fi 管理路径的情况。本轮没有测量当前隧道路径，
   也没有制造断网。执行破坏连接的验收前，应建立并验证独立于模组的管理路径；
   无法证明独立性时拒绝会中断连接的写操作。补充虚拟路由正常但底层走 RNDIS，
   以及路径变化、不可用时的测试。

2. **P2 — 被动流量速率跨接口使用旧计数。**
   `Network.snapshot` 的 `self.previous` 只保存时间与计数。
   `Agent.sample -> Network.snapshot -> rx_bps/tx_bps` 因而会在设备重新发现后，
   用新接口计数减去旧接口计数。模拟从 `rndis0` 切换到 `rndis1`，一秒内计数
   从 1,000 变为 1,000,000 字节，两方向均错误显示 7,992,000 bps。新接口首个
   样本应为不可用。应跟踪接口身份或代次，在发现失败、接口替换或计数重置时
   清除基线，并覆盖新接口计数较大、消失后重现、同接口正常增量等情况。

## 建议开发顺序

先修复管理路径验证和接口代次计数，再补齐 P3-15 的模拟器与实机故障场景。从干净
提交构建发布包，先对照既有安装/回滚证据与 R06、P3-16 的条件，再决定需要重跑的
项目。在独立管理连接可达的条件下，完成 P3-17 对停止/启动、重新接入和单一控制者
的准确要求。此前无线服务循环不能证明强制模组重置或自动恢复重试预算耗尽行为。

延续当前仅保留连接能力的范围：保留小流量诊断和被动计数，主动测速保持退役。
历史吞吐记录不作为新增验收要求。证据齐备前保持 P3-GATE 未完成。本轮仅增加文档，
不勾选任何路线图任务。

## P2 源码修复补记

问题：接口变化后，被动速率能否避免混用无关计数？后续修复涉及
`Agent.sample -> Network.snapshot -> rx_bps/tx_bps`：基线现在包含接口名和内核
ifindex，设备发现或计数读取失败时清除基线。接口身份变化或计数下降时，新区间
首个样本的速率为不可用。读取计数前后检查 ifindex，拒绝采样中途接口被替换的
结果。速率使用单调时钟计算经过时间，观测时间戳仍使用系统日期时间。

新增七项回归测试，覆盖正常增量、接口改名/替换（包括同名重建）、发现失败、计数
读取失败、计数重置、采样中途替换及系统时钟调整。修复前定向测试复现了跨接口
错误速率和失败后保留旧基线的问题；修复后 Jetson 后端 53 项测试全部通过。
修改仅影响被动观测，本轮未部署到设备，也未执行实机验收。
