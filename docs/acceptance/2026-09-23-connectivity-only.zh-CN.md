# 仅保留连通性的新一轮开发

## 问题与范围

在保留实验室选网检查的同时，让 UE 接入不依赖固定 Spark 管理端点或小区身份，并
移除主动测速。本轮仅支持 OCUDU + Open5GS。仓库没有 `.codegraph` 索引，因此直接
审阅源码与调用路径；此前完成的工程修复继续保留。

## 调用路径与影响

- `config.validate` 分别校验接入、观察策略、诊断和恢复字段；安装器通过
  `install -> backup -> migrate -> validate` 将 schema 2 迁移到 3，保留原频段和 PCI 参考。
- `Agent.sample -> Modem.snapshot / Network.snapshot / Network.probe` 拆开注册、PDU、
  数据验证、实验室策略与管理检查。会话或接口变化、过期或错误绑定的探测会使数据
  结论失效。模组写入仍要求当前管理保护有效。
- `Agent.auto_reconcile -> create(recover) -> launch -> execute` 先等待自然恢复，再有界
  尝试，冷却跨重启保留。诊断失败不会单独触发重置，取消会暂停自动恢复。
- 界面保留 Overview、Device Setup、History、Settings。API 参数、任务创建、启动及
  执行层均拒绝退役测速操作。SQLite 升级前备份历史，中断并退役旧未完成任务；保留被动计数。
- `render -> runtime.connectivity_server / health` 用固定小 HTTP 响应替代 ext-DN 测速。
  `verify_bundle` 用绑定 ICMP/HTTP 检查 N6。`upgrade_connectivity` 仅备份、更新自有
  ext-DN 文件与服务，重建失败时恢复原文件与容器。
- 旧 SQL/IMS UE 验收与核心网测速工具、测试移入 `archive/development-baseline-tests`。
  36 项旧 UE 测试不再作为当前回归覆盖；历史验收记录保持历史原貌。

- Jetson 后端：本地和 Jetson Python 3.10.12 上均通过 42 项测试。
- Spark 后端：Spark Python 3.12.3 上 51 项全部通过；本地 macOS 有一项原有的
  Linux peer-credential 测试跳过。
- 公共测试：两台设备各通过 80 项；原生测试后新增的三项 ext-DN 升级保留、拒绝及
  回滚测试已在本地通过。
- 四页桌面/手机浏览器测试覆盖配置持久化、取消、恢复、无测速导航、CSRF、SSE 过期及登录过期。
- 前端构建、类型、文档、发布、许可证和 shell 审计通过。
- 两台设备离线依赖安装与 `pip check` 通过。
- Spark 临时 `aoc-v2-corecheck-connectivity` 空核心网：12 个服务健康、8 个 NRF 注册、
  PFCP 关联成功，UPF 本地 N6 ICMP/HTTP 通过，所有停止退出码为 0，数据库在重建后保留。
  测试容器、网络、卷已清理。这不是 UE/GTP 或射频验收。
- 固定 ARM64 连通性镜像为
  `sha256:45fc43f140364eab399b351d5672e9501279669acf2d9420360f8d28a2f87d31`。
  隔离镜像检查确认不存在 `iperf3`。没有卸载其他业务的软件或停止其他服务。

- 首次基站重启发现 ext-DN 升级器漏更新外层 `release.json` 哈希，完整性校验因此
  拒绝启动。升级器现已将内外清单一起校验、备份、更新和回滚。操作人员成功执行
  审核后的一次性修复，保留原清单备份，并收紧 root 持有的 `bin`、`units`、

  完成，注册、PDU 和数据验证恢复。保留该自然恢复失败样本，不计入后面的五次成功循环。
- 自动恢复启用后，连续五次基站停启都观察到注册丢失，并在无人介入的情况下恢复注册、
  PDU 和绑定数据验证。恢复时间分别为 **54.25、25.00、25.74、57.68、20.35 秒**。
  这些循环未观察到恢复任务暂停标志的切换，不能据此证明执行过自动 CFUN 重试。
- 一次 Open5GS 核心网停启及其依赖基站重启通过。自动恢复暂停时，UE 在
  **77.94 秒**内自然恢复注册和数据。12 个服务恢复健康；订阅数据库卷及其创建时间
  保持不变，UE 注册成功。
- 管理连接使用经 Spark 直达 Jetson Wi-Fi 的 SSH，回程路由也已确认走 Wi-Fi；
  Tailscale 本身仍优先经过实验数据链路。五次成功基站循环记录 356 个持续心跳，
  最大间隔 **2.05 秒**；核心网测试记录 109 个心跳，最大间隔 **1.21 秒**。
  旧 Jetson 控制器均未运行，当前串口启动守卫通过。

另有一次早期自动模式测试因并发只读查询争用维护锁而中断；控制脚本已恢复基站，
并补上仅针对只读查询锁忙的有限重试。该次不计入五次完整循环。断网时过期的 UE
证据显示为未知；使用独立 Wi-Fi 心跳区分模组采样过期与真实管理连接中断。
