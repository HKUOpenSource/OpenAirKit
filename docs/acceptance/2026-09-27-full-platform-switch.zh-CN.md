## 首次操作结果与修正

操作员反馈第二台已成功离线安装，但 takeover 阶段出现
`ModuleNotFoundError: No module named 'serial'`。准备脚本在没有应用依赖的
系统 Python 进程中调用了 takeover。收尾逻辑已停止 OCUDU、恢复 OAI 并通过
OAI 验收。独立检查确认：目标发布已安装，其虚拟环境可以导入 pyserial 3.5，
OAI active，两个 OCUDU 服务 inactive，维护助手尚未安装。

第一台反馈 `New route verification failed`。独立读回确认路由已经正确添加，
原因是 iproute2 将协议号 187 输出为标准名称 `isis`，而准备脚本要求数字字符串。
使用 `ip -N -j` 后正确显示 187。该路由仍存在，待核对所有权并在测试结束后清理，
没有将此次结果表述为路由已回滚。

修正后的脚本强制输出数字协议号，并使用应用虚拟环境执行 takeover。新增
`finish-install` 操作验证已安装发布和受保护配置，要求状态仍为本次失败后的
未 commissioning、无维护批准，再继续执行，不重装、不替换控制台密码。批准包
及发布哈希不变。六项本地检查通过：解释器选择、数字协议读回和四项路由安全检查。
修正脚本已同步两台设备；第二台通过完整已安装发布校验、运行环境导入和只读
bootstrap 检查。本次仅修正私有测试脚本，没有修改部署的 OCUDU 发布。
