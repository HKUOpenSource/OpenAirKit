# Astryx console migration — 2026-09-23

[简体中文](2026-09-23-astryx-ui.zh-CN.md)

The Jetson Console and Spark Platform now use official Astryx components and
the unmodified Neutral theme. Spark 0.2.0 and Jetson 0.5.1 are deployed to the
devices; see the [initial deployment results](2026-09-23-astryx-deployment.md) and
[Jetson live update repair](2026-09-23-jetson-live-stream.md) for validation and
remaining operational limits.

## Scope and component mapping

| UI surface | Official components |
| --- | --- |
| Application and mobile navigation | AppShell, TopNav, SideNav, SideNavItem, DropdownMenu |
| Page composition and topology evidence | Stack, Grid, Card, Heading, Text, Link |
| Forms and filters | TextInput, Selector, SegmentedControl, Switch, Button |
| Status, errors and empty content | Badge, Banner, Spinner, EmptyState |
| Evidence and task details | Table, MetadataList, Collapsible, ProgressBar |
| Operation confirmation | AlertDialog |
| Signal and metric history | Charts Chart, ChartAxis, line |

The previous custom styles and SVG charts were removed. Topology is expressed
as evidence cards with links and status labels. The only shared CSS controls
page sizing, wrapping and spacing using official theme tokens. Small local
wrappers map domain states to official Badge variants or data into official
components; they do not implement alternative controls. Lucide icons match the
Neutral theme's dependency version.

## Dependency contract

Core, Neutral and Charts are all pinned to `0.6.2-canary.d72e4d6` in both apps.
Charts requires the matching Core prerelease; combining stable Core 0.6.2 with
this Charts build would violate its peer dependency. StyleX is pinned to 0.19.0,
Lucide React to 1.18.0. All package locks are committed source inputs.

This deliberately accepts a Charts prerelease to meet the requirement to use
Astryx throughout. Upgrade the three Astryx packages together after repeating
browser validation. No runtime npm/CDN connection is needed: Vite includes the
code and official CSS in each build. Builds also emit dependency license texts
as `THIRD_PARTY_NOTICES.txt`, including pinned upstream copies missing from two
npm tarballs. The combined bundle currently triggers Vite's 500 kB chunk advisory;
route-level loading can be evaluated if device measurements show a need.

## Question, call paths and impact

Question: can both existing React consoles use official Astryx throughout
without changing hardware or evidence semantics? No `.codegraph/` index exists;
source, package types and published component implementations were inspected.

- `main.tsx → UIProvider → Theme / LinkProvider → AppShell → route pages` owns
  theming, client routing, accessible navigation and mobile drawer state.
- Jetson `api / SSE → App → page context → Fields / JobPanel / MiniChart`
  preserves commissioning checks, CSRF, manual task execution, recovery,
  maintenance, stale evidence and diagnostic export.
- Spark `api / SSE → freshView → page components → Trend` preserves metric
  ownership, registration-versus-connectivity labels, stale current values,
  historical values, units and the selected time window.
- Chart adapters convert timestamps and valid numeric values, preserve null
  gaps, and break Spark series across missing intervals. A single Spark point
  keeps its position in the selected window. SSE still updates the headline
  independently of history queries.
- `vite.config.ts → frontendLicenses → dist/THIRD_PARTY_NOTICES.txt` includes
  browser dependency notices in the existing release payload.

The UI migration retains the backend API routes, device configuration, radio/core
control protocol and deployment layout. The requested Identity follow-up changes
the subscriber display projection as described below. The separately requested P2
passive-rate fix remains in this working tree.

## Device Identity follow-up

At the user's request, `open5gs.parse_info → collector → authenticated snapshot /
devices API → DeviceTable` now carries the full numeric subscriber identity as a
string, preserving leading zeroes. Both AMF-correlated and SMF-only records follow
this rule; hashed resource IDs and correlation checks remain unchanged. Previously
stored masked-only records cannot be reconstructed until a new observation arrives.

The subscriber inventory shows Identity, State, PDU addresses, DNNs and Last seen.
The redundant source subtitle and trailing detail link are removed; Identity opens
the detail page, where source and correlation remain available. Radio-context
columns remain in the radio inventory. Wide tables use Astryx's internal,
keyboard-accessible horizontal scroller with readable column widths.

Diagnostics still redact identities, and collector event messages keep their masked
subscriber label. Tests use synthetic identities, including a leading-zero case,
and verify authenticated display/search, diagnostic redaction, exact inventory
columns and mobile table scrolling. Production identities and screenshots are not
stored in this repository.
