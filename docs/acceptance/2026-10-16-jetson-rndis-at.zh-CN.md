## 问题、调用路径与影响

问题：RNDIS 数据网口已成功创建，为什么 commissioning 在 `AT` 命令上超时？

本工作区不存在 `.codegraph/` 索引。源码检查沿
`manage.commission → hardware.discover → Modem.fingerprint → Modem.open`
进行；服务的 `site_guard` 和 `network.inspect` 同样使用 `hardware.discover`。

RNDIS 启用后的实测 USB 布局如下：

| 接口 | 功能 |
| --- | --- |
| `00/01` | RNDIS 控制 / 数据，绑定 `rndis_host` |
| `02` | DIAG，第一个串口功能 |
| `03` | GNSS，第二个串口功能 |
| `04` | AT，第三个串口功能 |
| `05` | Modem，第四个串口功能 |

原来固定的 AT 接口 `02` 在该布局下选中了 DIAG。修正版示例改用 `04`；配置只
允许受支持的显式编号 `02` 和 `04`，发现逻辑核对完整串口 / 数据接口布局，
在打开串口前拒绝编号不匹配。串口在前、数据接口为 `04` 的布局仍使用 AT 接口
`02`。未知布局和多个匹配模组都会被拒绝，不依赖 Linux 的 `ttyUSB` 编号选口。

站点引导脚本还遇到了 `nmcli` 在创建连接时拒绝设置 `connection.uuid` 的问题。
改为加载固定 UUID 的专用连接文件后已解决；驱动匹配和 `never-default` 设置
通过设备上的 libnm 验证。该站点引导脚本为私密部署工具，不是新增的仓库部署入口。
