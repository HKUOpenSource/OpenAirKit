# Jetson 蜂窝 / Wi-Fi 自动切换 — 2026-10-16

[English](2026-10-16-jetson-cellular-failover.md)

## 结果

**一次真实 gNB 中断的有界回退、切回验证通过。** 停机请求后约 **11 秒**，
现有平台将普通 IPv4 默认出口切到 Wi-Fi。启动请求后约 **61 秒**恢复蜂窝
数据探测，再经过约 **23 秒**将默认出口切回蜂窝；从启动请求到切回合计约
**84 秒**。

独立管理 SSH 会话在整个流程中保持连接，并在观察完成后正常退出。
约 174 秒的故障、恢复窗口内，Wi-Fi 网关对记录到的 **174 个探测序号全部回复**。
绑定 Wi-Fi 的公网 ICMP 存在部分丢包，因此不能宣称所有管理网络数据包均无丢失。

gNB 配置保持一致，核心网和平台服务持续运行，切回后又完成 30 秒健康观察。
没有执行第二次故障、手动切换路由或手动模组恢复。

## 有界操作与管理保护

- 用户在 Spark 终端运行准备好的一次性管理员脚本，只停止本项目 gNB，
  保留核心网和 Jetson 平台运行；停机请求约 60 秒后发起启动。
- 停止前核对运行的二进制、已安装运行时清单，以及渲染器能否复现当前配置。
  在停机前启动脱离终端的独立恢复看护，父进程退出或约 70 秒到期时发起启动。
  本次由父进程正常请求触发恢复。
- 管理使用本机经 Spark 跳板到 Jetson Wi-Fi 地址的已认证 SSH 连接。
  直连网段返回路由保持在 Wi-Fi，不依赖实验蜂窝默认出口；独立心跳维持同一
  SSH 会话，覆盖整个流程。
- Spark 脚本重复检查 Wi-Fi 侧 SSH 端点及受限临时观察端点；管理保护失败会
  提前请求恢复无线，本次未报告该异常。
- Jetson 观察器仅查询路由、链路及服务状态并发送 ICMP。试验工具未写路由、
  SIM 或模组设置，默认路由变更由现有平台自行完成。
- 探测分别覆盖 Wi-Fi 网关、绑定 Wi-Fi 的公网地址、绑定蜂窝的 UPF，以及
  没有专用诊断主机路由的普通公网地址。注入前所有必需基线通过。
  首轮只读预检选用的普通目标不响应，数据已保留，该轮没有注入故障。

从停机请求到启动请求的主动等待约 60 秒；计入启动耗时后，服务实际处于停止状态
约 64.48 秒。

## 证据与最终状态

中断期间出现平台拥有的 metric 5 Wi-Fi 默认路由，metric 10 蜂窝默认路由被移除，
原 DHCP 默认路由保留。普通公网路由读回选择 Wi-Fi，独立无绑定探测收到 3/3
回复。切回后恢复 metric 10 蜂窝默认路由，Wi-Fi 仍可回退，普通公网路由重新选择
蜂窝。RNDIS 接口始终存在且保持载波，因此不是删除主机接口后由内核直接换路由。

包含基线及恢复过程的全部 **408** 个路由、服务样本中，管理路径始终为 Wi-Fi，
Jetson 平台服务始终运行。故障、恢复窗口内记录到的探测序号结果如下：

| 探测 | 有回复序号 / 观察到的序号 |
| --- | ---: |
| Wi-Fi 网关 | **174 / 174** |
| 绑定 Wi-Fi 的公网目标 | 166 / 174 |
| 普通公网目标 | 160 / 174 |

窗口按观察时间归属，边界可能相差约一次探测。普通公网丢失包含切换前预期的中断，
公网目标的丢失也如实保留，没有因 SSH 会话成功而隐去。

管理 SSH 进程未被替换，以退出码 0 正常结束。故障、恢复区间加五秒前置窗口保留
179 个连续远端心跳，最大生成间隔约 1.002 秒。该值是远端心跳生成间隔，
不是网络 RTT，也未测量本机接收是否存在亚秒级停顿。

Console 随后显示 5GS 已注册、数据 PDU 在预期地址池内活跃、实验策略匹配、
蜂窝绑定探测健康且出口为蜂窝；PDU 在配置的池内获得新地址。收尾绑定 RNDIS
的 UPF 探测收到 3/3 回复，绑定网口的 ext-DN HTTP 返回预期健康响应。

gNB 配置 SHA-256 保持为
`01d31327038022cb0c6d7112eebbaf2705468dfe6c535d595bf44ee5a1ab0394`。
原核心网及监测服务持续运行。独立看护结束并被回收，临时观察端口关闭，
ICMP 进程退出，管理心跳正常结束；未留下永久测试服务或网络修改。
