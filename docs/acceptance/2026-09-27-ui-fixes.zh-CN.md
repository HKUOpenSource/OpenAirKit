## 范围与实现

每台 Jetson Console 负责本机状态，Spark 展示自身基站可获得的证据。没有新增全局
设备状态、设备群管理或强制身份横幅。两套界面继续使用 Astryx Core、Charts、Neutral
和现有 UIProvider；新增 CSS 仅用于切换 Setup 响应式布局。运行界面保持英文。

仓库没有 CodeGraph 索引。本轮问题是：哪些 UI 数据路径会误述本机状态、隐藏操作错误，
或阻止用户查看已经保留的证据？

| 调用路径 | 修复与影响 |
| --- | --- |
| Spark freshView / freshDevice → activeDataSession → Overview / Devices | Active 要求新鲜、已注册且明确 active 的数据 PDU 证据。分开注册、会话和新鲜度筛选，移除订阅者无法匹配的 Connected 选项；筛选无结果时提示调整条件。 |
| Jetson 确认 → confirmOperation → jobs / run | 创建后立即保留任务 ID，再请求执行。重试先读取原任务，仅运行 ready/paused 的恢复任务，不因已知创建成功后的执行请求失败而另建任务。错误留在 Astryx 确认框内，Setup 仍需单独确认执行。 |
| Jetson JobPanel / maintenance；Spark Operations → API | 展示请求中状态并禁用竞争操作。Spark 轮询读取错误与提交/取消错误分开，成功轮询不会清除操作错误。 |
| Jetson History / Recent activity → history / metrics | 独立于任务数量刷新，取消被新查询替代的请求，使用事件游标，已加载的旧页保留至明确刷新。标出事件 30 天、指标 7 天的保留范围；图表展示最后有效样本时间和实际查询时间轴，多日范围包含日期。 |
| Spark History → 已鉴权 history/catalog → Store | 分页列出保留的实体和指标名，包括离线实体和最新样本已没有的指标，不再依赖当前快照。 |
| Spark Events → 已鉴权 events/kinds → Store | 事件类型来自独立的保留分类，不随筛选结果或当前页消失；取消旧请求，避免旧请求完成后覆盖新查询的加载状态。 |
| gNB → Astryx 摘要 / Collapsible / Trend → HistoryProvider | 前置 N2、无线上下文和流量；信号、主机资源、运行与配置详情默认折叠。同一实体、时间窗和刷新周期内的图表共享请求，缓存有数量上限，并随已登录界面卸载而清除。 |
| Jetson Setup → Astryx Table / Card / MetadataList | 增加 Matched / Different / Observation only / Unknown，地址按地址池成员关系判断；展示前提条件和计划动作。768px 以下将当前值、目标和判断放在同一卡片中，不将无线观测策略当作已编程的锁定配置。 |
| Spark 外壳 / StatusSummary → Astryx SideNav / Banner | 历史、运维、诊断进入主导航；采集标签为 Live data / Evidence stale，翻译故障原因并统一时间格式。区分初次未登录与会话过期，初次状态加载失败时提供重试。 |

## 授权后的模拟器操作验收

用户明确授权后，使用 Browser 验证真实本地 Web API。Jetson 开启 simulation，Spark
使用临时 Unix socket 上的无硬件动作模拟执行器。没有操作生产设备、无线命令、部署
或外部服务。

- Jetson：延迟后失败的 Setup 提交将错误保留在确认框内。重试创建一个手动计划，
  执行一步后暂停，随后取消成功；取消请求中运行和取消按钮均禁用。
- Jetson 恢复：创建成功后注入运行请求失败。重试先读取原任务，再执行同一 ID，最终
  完成。请求记录确认重试没有另建任务。
- Spark：延迟提交时确认按钮显示加载并禁用；失败经过三次成功后台轮询仍在弹窗内。
  重试创建模拟运行任务。取消失败经过十一次成功轮询仍然可见；重试取消成功，操作
  按钮恢复可用。
- 390px 下 Jetson 错误弹窗无溢出，Back 关闭后焦点回到 Create setup plan。检查中
  发现并去除了重复的“Error:”前缀，Jetson 前端重新构建通过。

此前自动审批阻止的模拟器提交已通过用户明确授权解除，以上定向操作验收通过。
全部键盘、读屏、200% 缩放和实机验收仍不属于本轮结果。检查结束后清理本地服务和
视口覆盖。
