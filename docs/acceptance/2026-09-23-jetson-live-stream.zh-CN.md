# Jetson 实时更新修复 — 2026-09-23

[English](2026-09-23-jetson-live-stream.md)

Jetson 0.5.1 移除 SSE 定时断开，并减少等待独立网络探测的时间。设备证据仍在
20 秒后过期，实时更新缺失仍在 10 秒后判为过期。页面分别说明证据过期和更新
中断，不再将两者统一描述成实时流故障。

## 证据与原因

已部署的 0.5.0 Web 和设备服务没有自动重启或日志异常。72 秒内的 36 次只读
采样均显示已注册、数据会话激活、数据连通性验证正常。缓存证据年龄达到
19.2 秒，接近 20 秒阈值。实时流请求均返回 200，每隔 21–22 秒重新建立；
服务端代码会在约 15 秒后主动结束实时流。

用真实缓存状态和页面的新鲜度规则进行时序复核，在距上次模拟事件仅 1.38 秒时
复现过期判断：页面保留的证据年龄为 20.09 秒，而后端已拥有 8.34 秒前的证据，
连接验证正常。这是只读时序复核，不是用户登录后浏览器的抓包；尚未独立确认
用户实际使用的浏览器及转发链路。

## 问题、调用路径与影响

问题：设备健康时，页面为何仍提示实时流不可用？仓库无 CodeGraph 索引。
检查路径为 `Modem.snapshot → Agent.sample → 四项网络探测 → 缓存状态 →
API events/stream → App stale → Banner`。

- 四项固定、绑定接口的只读探测改为并行执行，保留命令超时和取消机制。硬件锁
  仍覆盖整个采样，调制解调器命令和网络修改仍串行。各项探测独立记录失败，
  必需证据失败或未知仍会阻止已连接声明；不会通过推迟时间戳掩盖旧数据。
- SSE 在客户端连接期间持续开放，每次更新在执行器调用前后检查认证。注销或
  会话过期会结束流；执行器异常发送 `unavailable`，随后在同一连接重试。
  响应禁止缓存，并给出一秒重连提示。
- Web 优雅关闭上限为五秒，低于 systemd 的 20 秒停止期限，避免长连接无限
  阻塞部署过程。
- 页面分别显示实时更新中断、设备证据过期，两种情况下均不保留当前已连接
  声明；新鲜度阈值不变。
