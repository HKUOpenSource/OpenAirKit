# Spark troubleshooting

[简体中文](troubleshooting-bs-spark.zh-CN.md)

## Monitor unavailable or missing radio metrics

Check `aoc-control.service`, `aoc-observe.service`, `aoc-monitor-web.service`
and `127.0.0.1:8877`. A listener conflict stops installation before the current
release link changes. If SSE is disconnected while health remains available,
inspect collector freshness and authentication expiry before restarting services.

If host, core or bridge metrics work while RAN scheduler metrics are unavailable:

- Verify `ss -tna | grep :8879` shows both a listener on `127.0.0.1:8879` and an
  `ESTAB` connection from `aoc-observe.service`.
- Verify `127.0.0.1:8879` is not blocked by another service, and confirm `8001`
  is free of legacy metrics guard rules (`sudo nft -nn list table inet aoc_v2_metrics_guard`
  should list `tcp dport 8879 meta skuid != 0 reject`).
- Confirm `aoc-v2-open5gs-core` bridge inspection (`docker network inspect aoc-v2-open5gs-core`)
  returns an active bridge interface matching `collector.py::bridge_interface()`.

## Radio start failure

Run `aoc-v2ctl status`, inspect the lifecycle record and radio journal, and
verify that no process owns the B210. Distinguish a failed unit from an active
process with no N2. Do not repeatedly restart a radio that failed its stability
window; preserve its log and invocation identifier.

- Check `systemctl show aoc-v2-radio.service -p DropInPaths` to confirm no stale
  `/run/systemd/system/aoc-v2-radio.service.d/*.conf` overrides are masking
  persisted settings.

## Core function unhealthy

Inspect only the named container and its dependencies. Record exit code, OOM
state and health reason. N2, N3, N4 and N6 are separate evidence domains; one
healthy interface cannot clear another failure.

If `mongo` (8.0.30) fails on Linux 7.0+ kernels (e.g., `7.0.0-1019-nvidia`) due
to TCMalloc per-CPU rseq allocation, verify `GLIBC_TUNABLES=glibc.pthread.rseq=1`
is present in `/opt/agentic-ocudu/v2/core/compose.json` (generated by default in
`stacks/open5gs/compose/render.py`).

## Device shown stale or disconnected

Compare current gNB process generation, RAN-context timestamp, core session and
PDU endpoint. A session reported before a gNB restart remains historical until
new correlation evidence arrives. A previous IP or throughput result cannot
mark it current.

## RF errors or low throughput

Compare underflow, overflow and late counts within the same gNB invocation.
Verify `aoc-v2-cpu-latency.service` is `active` (holding `/dev/cpu_dma_latency=0`)
and confirm CPU affinity/realtime drop-ins (`realtime.conf`) are active if
co-located workloads share the host. Check persisted B210 `rx_gain` (`54`) and
`cell_cfg.pusch.max_ue_mcs` (`24`). Record RSRP, RSRQ, SINR, antenna
configuration and a three-sample bound UE benchmark. Change one radio, scheduler
or runtime variable, keep a rollback, and repeat under equivalent physical
conditions.
