# 实施阶段与完成标准

## P0：仓库初始化（本次完成范围）

目录边界、环境资源规划、版本候选、systemd 模板、监控契约、离线校验与负向测试。原始调研归档。没有远端部署变更。

## P1：独立构建与核心网

1. 实时复查 Spark 路由、Docker IPAM、端口和主机依赖，确认候选资源可用。
2. 在本项目路径构建固定 OCUDU 提交，记录编译器/UHD/依赖版本，完成无射频测试。
3. 确认各 OAI NF 与数据库 ARM64 镜像、digest、配置兼容性，完成 Compose 与数据库初始化。
4. 导入经授权的独立订阅配置，验证服务健康和新 UPF/N6 路由，不动旧库。

出口：新核心网可独立启动和停止，不影响原 OAI；未通过此阶段不进入发射测试。

## P2：生命周期与切换

实现 core/radio wrappers、配置渲染、安装/卸载、状态与失败恢复入口。替换 `.in` 参数后进行 `systemd-analyze verify`，使用隔离替身服务验证双向互斥、停止传播、超时及重试。核对原 Biverge iperf3 故障是否已解决。

出口：Biverge 文件与脚本无改动；新 target 的启动/停止资源边界正确；原脚本能触发完整切回。随后在已安排的射频窗口完成实际 B210 交接。

## P3：OCUDU + 独立 OAI 端到端

补齐频点、TDD、增益、B210 序列号、TA/slice/DNN/订阅。验证 N2、注册、PDU、用户面及反复切换，检查同 SIM 的认证重同步。记录吞吐、重传、USB/实时调度与稳定性。GPU 加速和 CU/DU 分离不作为首阶段前提。

出口：通过 `docs/switching.md` 验收矩阵；有明确的基线、故障日志和恢复记录。

## P4：独立监控 MVP

实现模块内 backend/frontend、OCUDU/OAI/host adapters、观测状态与历史；完善数据契约验证。提供真实指标，不伪造无法采集的 UE/会话身份。认证、访问发布和权限边界单独验收。

出口：新平台能区分进程就绪、N2、UE 注册、PDU 和用户面状态；Biverge 是否在线不影响监控。

## 后续

IMS/VoNR、CU/DU 分进程、7.2x O-RU、GPU 后端和长稳压测分别立项，不能由当前骨架推定已支持。
